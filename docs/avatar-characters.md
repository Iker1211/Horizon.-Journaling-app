# Character profile avatars

The five figures are the user's original vector assets from `/home/velez/repos/my-turborepo/curated-figurine-assets/`, copied unchanged to `public/images/characters/`: otter, yak, pterodactyl, bear and penguin. No image generator, background plate or circular crop is used for the figures. Their silhouette, pose, tilt and a small silhouette-following shadow supply the identity. The whole profile button is at least 64×56px on compact screens and stays with the sticky header, respecting its existing Android insets. Hover motion is brief and disabled for reduced-motion users; there is no idle animation.

`profiles.avatar_character` is a nullable constrained text field. The database and client accept only the five catalog IDs. Existing owner-only RLS continues to protect it; the migration grants authenticated users permission to update that column without changing RLS. No selection is written to auth user metadata. Old accounts fall back to the otter when they have no uploaded photo. Existing personal photos are retained when switching to a character, and can be selected again; uploading a new photo clears the character choice. Account exports already include the field through the exported profile row. Account deletion removes it with the profile.

Profile text inputs are preserved when a character save updates the profile. Choosing a character persists immediately, disables further choices while saving and confirms success only after the account update completes. A failed update leaves the preceding selection active with a retryable error. No connection disables the selector. Built-in assets are bundled for web and Capacitor Android.

Apply `supabase/migrations/20261018000000_add_avatar_character.sql` before deploying the frontend. The additive migration preserves existing photos, versions, account policies and records. Rollback: deploy the preceding frontend first, then drop `profiles.avatar_character` if needed. No uploaded photo needs to be deleted or migrated.

Validation: the running development preview uses the real ProfilePage, picker and navbar with a synthetic owner, while sensitive account controls are inert. Checked successful selection, selection retained after reload, failed-save preservation, and a name edit surviving a character change. Responsive checks at 320/360/393/768/1280px showed no horizontal overflow; the character remains at the top while the page scrolls. Profile axe checks detected and prompted correction of an existing unlabeled upload input. Local PostgreSQL tests passed the actual migrations and negative cross-account read/update tests, plus rejection of unknown character IDs. Service regression tests also cover catalog validation and retained personal photos. Native-device rendering remains unverified because no Android device is attached.
